# ADR 0009: Replace the Tech Stack mascot with a sprite loop

- **Status:** Accepted
- **Date:** 2026-09-09
- **Amended:** 2026-09-10 — slowed the base playback from 3 fps to 2.5 fps, slowed only the expressive tail, added four tail in-between frames, expanded the full loop with sixteen reference-guided transitions, then replaced bounds-centering with character-anchor registration. After local review found that the supplied and generated source frames had materially different native character sizes, a deterministic per-frame scale calibration was added around the common head anchor. The crop pass was then tightened to remove small components touching any cell boundary, including a 4px local antialias halo, after a cross-cell blue residue was reproduced at the high-kick pose. The loop was then expanded with two additional ten-pose action groups and three generated transition frames per connection (144 frames total). Boundary matte removal now covers both light and black generated backgrounds, and isolated matte residue is excluded from geometry bounds. The GIF encoding was also changed to full opaque canvases after transparent differential frames were found to make pose switches visibly shake.
- **Scope:** Published `README.md` and `README.zh.md` Tech Stack right cell

## Decision

Use the user-supplied 4×4 chibi sprite sheet as the Tech Stack mascot baseline, then add two ten-pose action groups: `C01–C10` (evade/counter) after `5` and before `9`, and `D01–D10` (observe/understand/celebrate) after `15` and before `16`. Keep every key pose proportional on a centered 320×320 canvas, add three transition frames per connection, and publish two infinite-loop GIFs. The playback order and connection list are the single source of truth in `scripts/tech-stack-mascot-sequence.js`; the loop contains 36 key poses, 36 connections, and 144 binary frames.

- `assets/tech-stack-knight-v2.gif` — `#ffffff` light-theme background
- `assets/tech-stack-knight-v2-dark.gif` — `#0d1117` dark-theme background

Both GIFs contain 144 frames and are selected through the existing `<picture>` theme switch in both README locales. The original punch cadence remains 400 ms source holds with 90/90/180 ms transition timing in the fast section; the old expressive tail keeps its 600 ms sources and 150/150/300 ms transitions. The C group follows the fast combat cadence and uses a 120/120/260 ms recovery into pose `9`. The D group uses 550/650/700/750/900/900/750/600/850/1000 ms key holds and progressively slower 180–640 ms transition steps. This produces a measured 39.41-second loop with three distinct transition frames per connection. A common base scale plus separate deterministic calibration tables normalizes new-frame character size toward a safe `122px` head-silhouette target without clipping the compact crouch pose. Every GIF image descriptor covers the whole `320×320` canvas at `(0,0)` and has no transparent index, so rendering a pose is independent of whichever frame came before it.

## Rationale

The sprite sheet already contains the main pose sequence, so deterministic grid cropping preserves the supplied artwork and keeps the animation predictable. The two generated 5×2 sheets are cropped on rounded measured grid edges and passed through boundary-connected neutral-matte removal; this handles both checker/gray matte and pure black generated backgrounds without touching warm character pixels. The supplied high-kick art still uses the existing boundary-component cleanup for cross-cell residue. The new action groups were generated as key poses plus three reference-guided transition frames for each of the 22 connections touching C/D; no transition is implemented as a crossfade. The generated frames and supplied poses are not all drawn at the same native character scale, so anchoring position alone cannot prevent visual size pulsing. Before GIF encoding, each new transparent `320×320` frame is registered around a character-specific warm-color head anchor at `x=132`, `y=115`, using `TARGET_SCALE=0.9` and its deterministic calibration correction. The geometry pass uses the main alpha-connected character component plus nearby action components, excluding isolated edge matte residue from the scale box. The safe `122px` head-silhouette target intentionally leaves padding for extended limbs and celebration effects. Full alpha bounds are kept so limbs and effects are visible, but they are never used to position or scale the character: transient question marks, impact trails, and celebration particles cannot perturb the character geometry. The final palette encoding composites each registered pose over its theme background and disables GIF offsetting and transparent-difference optimization. A fixed, opaque `320×320` image per logical frame prevents decoder state from leaking between actions; it complements the geometric calibration by removing the remaining window-level source of shake. Separate light and dark encodes keep the character legible against GitHub's two themes.

## Fallback and rollback

The previous `assets/mascot.gif` and `assets/mascot-dark.gif` files remain unchanged as inactive rollback assets. They are hidden from the rendered README through source comments, documented in `docs/assets-reproduction.md`, and should not be deleted without a separate decision.

# 04 · Playful Personality（玩趣人格声线）

> GitHub Profile Polish · Voice Research  
> 类别定位：有辨识度、好玩、略带不羁，但仍显专业能力——不是 meme 堆砌。

---

## Category definition

**Playful personality** = 用轻松、带一点调侃的第一人称说话，同时用**可验证的作品与清晰信息**证明你会做事。

| 维度 | 要有 | 不要有 |
| --- | --- | --- |
| 语气 | 像聪明朋友在聊天；可自嘲、可旁白 | 像段子手刷屏、整页 emoji、无信息梗 |
| 能力信号 | 具体项目、栈、结果、链接 | 「我很幽默」却无 pinned 作品 |
| 幽默密度 | 每 2–4 句可有一次轻触；玩笑服务记忆点 | 每句都梗、双关淹没技术事实 |
| 读者感受 | 「这人有趣 *且* 靠谱」 | 「好玩但不像能合作」 |

一句话标准：**玩笑是调味，交付物是主菜。**

## Catchphrases / wording habits + quotes

### 1) Cassidy Williams — 轻浮开场 + 立刻落到「我做的东西」

**习惯**
- 称呼读者像熟人小圈子：`Hello, nerds`
- 并列三拍节奏：`memes and dreams and software`
- 贬低自己身份头衔、抬高兴趣：`Outside of that fancy title…`
- 口癖式拖长音 / 口语：`mooore`、`if I'm in a bloggy mood`
- 括号旁白限定边界：`(within reason)`
- 作品列表用「你可能会喜欢」而非「我的卓越成就」

## Sentence patterns（句式 / emoji / 玩笑 / 旁白）

### 共同句式骨架

```
[轻松称呼或 Hi] → [一句人设/兴趣并列] → [立刻给证据：产品/链接/列表]
→ [可选：括号旁白或半句自嘲] → [明确 CTA：newsletter / 项目 / 联系]
```

### 模式拆解

| 模式 | 结构 | 示例来源 | 学生可挪用强度 |
| --- | --- | --- | --- |
| 三拍并列 | A and B and C | memes / dreams / software | ★★★ 很安全 |
| 假谦虚开场 | 轻描淡写能力 → 作品打脸 | "I code on occasion…" | ★★ 慎用，需真有作品 |
| 头衔降调 | fancy title → 我其实还是… | cassidoo | ★★ 学生可改成「还在学，但已经在做…」 |
| 能力 + 怪味收尾 | 正经列表 + or a little strange | CoolDotty | ★★★ |
| 朋友测试法 | 对朋友怎么说 → 写进 profile | levelsio | ★★★ 首选 |
| 括号旁白 | 主句正经 (asides) | within reason / believe it or not | ★★★ |
| Hook 一行 | 作品名 + 一句荒诞但清晰的卖点 | Fish God / chess dating | ★★ 适合 pinned 描述 |

### Emoji 密度观察

| 来源 | 密度 | 用法 |
| --- | --- | --- |
| cassidoo README 正文 | **极低**（几乎无） | 玩趣靠用词，不靠符号 |
| cassidoo.co | **极低** | 标题与正文干净 |
| CoolDotty | **中低** | 主要在 badge / 分区，正文仍是完整句 |
| levelsio | **近零**（文中偶有引用推文装饰） | 语气靠短句与直球 |
| swyx | **声明喜欢 emoji**，正文仍克制 | 「spice up a core message」= emoji 服务信息 |

**可执行规则（学生 profile）**
- 全文 emoji：**0–4 个**足够；放在问候或分区标题即可。
- 禁止：技能墙每个语言一个 emoji、连续 🔥🚀💯、整行 kaomoji。
- 玩笑位置优先：**bio 一行、项目一行 hook、一处自嘲**；不要把 About 写成 standup。

### 玩笑类型（由稳到险）

1. **命名玩笑**（Flapjack Fwop、a little strange）——稳  
2. **身份玩笑**（fancy title / code on occasion）——稳，需有反差证据  
3. **场景荒诞 hook**（grumpy Fish God）——适合游戏/创意项目描述  
4. **嘲讽行业黑话**（vague jargon / big startup）——稳，显判断力  
5. **纯 meme / 屎上雕花自嘲连发**——险，学生档易 cringe

## Steal-for-profile do/don't（学生向 · 保持得体）

### Do ✅

1. **Bio 一行用「兴趣三拍」或「做 X 的人」**，不要职称堆叠。  
   - 例：`Building small tools, weird demos, and things I actually use.`
2. **About 前 2 句：1 句人设 + 1 句正在做什么**；第 3 句起必须是项目/链接。  
3. **Pinned 描述写 hook，不写「本项目旨在…」**：一句说清 + 可带一点怪。  
4. **用 levelsio 朋友测试**：朗读给同学听，听不懂就删 jargon。  
5. **旁白括号最多 1–2 处**（如 `(still learning)` / `(yes, it works)`）。  
6. **CTA 具体**：`Ask me about …` / newsletter / demo 链接，而不是 `Let's connect ✨`。  
7. **结构参考 CoolDotty**：能力段 → Featured 表 → 玩趣段（Playable / Fun bits），顺序先证明再耍宝。

### Don't ❌

1. 不要写 `⚡ Fun fact: I am very funny`（自我宣布好笑 = 通常不好笑）。  
2. 不要整页 GIF 猫图 + 「unlike my sleep schedule」类陈词（已成模板 cringe）。  
3. 不要用「passionate about leveraging synergies」同时又堆梗——双倍尴尬。  
4. 不要把幽默建立在贬低同学/性别/政治梗上。  
5. 不要只有 vibe、没有 repo：玩趣人格**靠作品托底**。  
6. 不要 emoji 密度大于信息密度。  
7. 学生档避免过度「大佬自嘲」（`I code on occasion`）——没有履历时像逃避能力证明。

### 可直接改写的学生模板（语气示意，非抄袭）

```markdown
### Hi — I make small things that hopefully don't break.

CS student. I like clean UI, slightly weird side projects, and shipping
before the idea gets too precious.

**Now:** learning [X], building [one concrete project + link].

**Things I made:**
- [Project] — one-line hook (clear + a little fun)
- [Project] — what it does for a human, not for a resume

Ask me about [2–3 real topics]. Coffee jokes optional; working demos preferred.
```

## Anti-patterns（反模式速查）

| 反模式 | 为什么失败 | 对照正例 |
| --- | --- | --- |
| **Meme dump** | 信号=娱乐号，不是协作者 | cassidoo：梗在开场，主体是作品列表 |
| **自我标榜好笑** | 「我很 funny」无证据 | CoolDotty：让 *项目名/hook* 好笑 |
| **模板自嘲** | sleep schedule / caffeine / 3AM 到处都是 | levelsio：具体产品名代替生活刻板印象 |
| **Jargon 伪装专业** | 不清楚你在做什么 | 「对朋友怎么说就怎么写」 |
| **全篇旁白** | 像回避正经介绍 | 旁白是调味，不是主结构 |
| **Emoji 技能博物馆** | 像 2019 README 生成器 | 正文近零 emoji，badge 克制 |
| **只有氛围没有交付** | 玩趣变成空心 | 每人样本都有可点链接的 ship 列表 |
| **攻击性阴阳** | 不羁变成刺人 | 刺「装腔文案」，不刺读者本人 |

## 给本项目的声线摘要（可写入 profile brief）

- **声线标签**：playful-competent / friend-explain / light aside  
- **幽默配额**：全文 1 个记忆点开场 + 0–2 个项目 hook + ≤4 emoji  
- **能力配额**：≥3 个可点击作品，About 中段必须出现  
- **禁止清单**：fun fact 自称好笑、猫 GIF 墙、jargon 段落、梗密度 > 信息密度  
- **验收朗读**：用「对朋友解释」读一遍；同学能复述你在做什么 = 过关。

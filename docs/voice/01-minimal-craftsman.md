# Voice Category 01 — Minimal Craftsman（极简工匠）

> 研究用途：GitHub profile polish / 学生独立开发者个人页文案参考  
> 日期：2026-08-01

---

## 1. Category definition（声音定义）

**Minimal craftsman** 优化的是：**高信号密度 + 克制气质 + 可验证产出**，而不是热度、梗图或「成长叙事」。

| 维度 | 这类声音在优化什么 |
| --- | --- |
| 信任 | 用作品与事实说话；少形容词，多名词与动词 |
| 可读性 | 短句、列表、一眼能扫完的结构 |
| 身份 | 「我做工具 / 做界面 / 做开源」比「我是全栈天才」更重要 |
| 情绪 | 安静自信；偶有温度（摄影、音乐、旅行），但不喧宾夺主 |
| 双语 | 可中英并存；专有名词与项目名保持原文 |

**一句话**：像打磨过的 README——干净、有立场、不喊口号。

## 3. Catchphrases / recurring wording habits（口头禅与用词习惯）

### 3.1 身份标签：短、可核验

- `fanatical open sourceror` / `design engineer` — Anthony Fu, https://antfu.me/
- `Full-Time Open-Sourcerer & App Maker` — Sindre Sorhus, https://sindresorhus.com/
- `Full-Time Open-Sourcerer. Focused on Swift & JavaScript. Makes macOS apps, CLI tools, npm packages.` — GitHub About, https://github.com/sindresorhus
- `Webmaster at Linear.` — Paco Coursey, https://paco.me/
- `Open Source Enthusiast` / `开源爱好者` — Kevin Deng / 智子, https://sxzz.dev/ · https://sxzz.dev/zh/
- `Seeking the meaning of existence.` — sxzz GitHub bio, https://github.com/sxzz

### 3.2 「做」与「打磨」动词簇（craft lexicon）

- `Dreaming up cool ideas and making them come true` — antfu.me
- `enjoy the process of crafting` — antfu.me
- `Crafting interfaces. Building polished software and web experiences.` — paco.me
- `Experimenting with magical details in user interfaces.` — paco.me
- `Implementing interfaces and interactions.` — paco.me / craft
- `imbuing quality` — paco.me（Now 区块）
- `Style principle: Minimal for reading, stable for diff, consistent` — @antfu/eslint-config README

### 3.3 克制的自我限定 / 诚实免责

- `this is still a personal config with a lot of opinions` — antfu/eslint-config
- `I suggest you review the changes every time you update. Or if you want more control… always feel free to fork it.` — 同上
- `Infrequent thoughts on design and code.` — paco.me（把「更新不勤」写成气质，而非缺陷）
- `Return to simplicity.` — paco.me Writing 列表

### 3.4 模块化 / 小而专注（sindresorhus 哲学句）

来自 https://sindresorhus.com/blog 列表可见的短句风格：

- `Make small focused modules for reusability and to make it possible to build larger more advanced things that are easier to reason about.`
- `Open source is not just about code, it's about people.`
- `It's time to move from Buffer to Uint8Array.`（技术立场一句说完）

包 README 习惯（https://github.com/sindresorhus/type-fest）：

- `A collection of essential TypeScript types`
- `Many of the types here should have been built-in.`
- `Either add this package as a dependency or copy-paste the needed types. No credit required. 👌`
- `PR welcome for additional commonly needed types and docs improvements.`

### 3.5 作品优先的链接句式

- `You can find my full projects list here.` — antfu.me
- `check out my latest app: Supercharge` / `latest blog post` — sindresorhus profile README（玩笑壳 + 实质链接）
- 项目一行描述：`Perfect dark mode in Next.js apps.` / `Plain text editor with a focus on performance.` — paco.me
- 终端隐喻列出产出：`$ cat creator.md` → 项目链接；`$ cat team.md` → 团队链接 — sxzz.dev

### 3.6 轻赞助 / 轻社交（不硬卖）

- `If you enjoy my work and find them useful, consider sponsor me and the ecosystem… Thank you!` — antfu.me
- `在爱发电上支持我` — antfu.me（中英自然并列）
- `Reach me at @pacocoursey or mailto:p@paco.me.` — paco.me

## 4. Sentence patterns（句式与版式文化）

| 模式 | 观察 | 示例倾向 |
| --- | --- | --- |
| **短 vs 长** | 首页以 **短句 / 碎片句** 为主；长句留给「动机一段」（最多 2–4 句） | Paco：连续名词短语句号断开；Antfu：一段热情说明后立刻转事实 |
| **第一人称** | 常见 `I` / `I’m` / `I’ve`，但频率受控；身份句可省略主语 | `Crafting interfaces.`（无 I）vs `Hey! I’m Anthony Fu…` |
| **第二人称** | 少用推销式 you；偶尔用于邀请 | `If you enjoy my work…`；`Reach me at…` |
| **Emoji** | **极低密度**。个人页正文几乎不用；包 README 偶尔 1 个点缀（👌）或风格徽章 | 避免「👋🔥🚀」开场轰炸 |
| **Badge 文化** | 工具 README 可用 **少量、功能性** badge（npm version、downloads）；个人主页叙事区不宜变成 shields 墙 | antfu eslint-config：克制 npm + 自有 code-style badge；type-fest：有 badge 但正文仍短句主导 |
| **列表 > 散文** | 项目、写作、团队一律列表或「一行一物」 | paco Projects / Writing；sxzz creator.md / team.md |
| **幽默** | 干、短、可跳过；不抢主信息 | Sindre profile 的 GIF 反讽；博客标题 `It's a trap.` |
| **双语** | 中文站点用简洁称呼 + 原文项目名；不把英文口号硬译成鸡汤 | antfu「哔哩哔哩」「爱发电」；sxzz「开源爱好者」 |
| **结构骨架** | Name → 1 行身份 → 2–5 句做什么 → 作品列表 → 次要兴趣 → Connect | antfu.me / paco.me 高度同构 |

**节奏口诀**：一行立住身份 → 一段说明热情（可选）→ 用列表证明 → 用链接收尾。

## 5. What to steal for a student GitHub profile（可偷 / 别偷）

### Do ✅

1. **一行身份，可核验**：`CS student · building CLI tools in Rust` / `学生，做小工具与笔记库`——对标 Sindre/Paco 的短标签，而不是「全栈架构师」。
2. **3 个 pinned 级项目，各一行结果导向描述**：学 Paco 的 `Perfect dark mode in Next.js apps.`——写清「解决什么」，别写「用了 React/Vue」。
3. **一段 ≤4 句的动机**（可选）：学 antfu 的 crafting 语气，但把「fanatical」降级为真实热情，例如对学习与开源贡献的具体兴趣。
4. **Connect 极简**：GitHub / Blog / Email 三选二即可；学 Paco 的 `Reach me at…`。
5. **中英择一主语言 + 关键名保留原文**：项目名、库名、协议名不翻译；中文分析/自我介绍可以简洁。
6. **诚实边界**：学 antfu 的「这是 personal / opinionated」——课程作业、实验 repo 可标注 `learning` / `wip`，比假装生产级更工匠。
7. **空也是设计**：没写的板块就删掉；学 sxzz——页面上几乎只有「我做了什么 / 我在哪些团队」。

### Don't ❌

1. **不要**堆 typing SVG、大段 github-readme-stats、十几个语言徽章当主视觉（那是另一类「showcase」声，不是本类）。
2. **不要**复刻 Sindre profile README 的整页 GIF——那是成名后的玩笑；学生页会像模板梗，不像工匠。
3. **不要**用空洞超级词：`passionate`、`ninja`、`10x`、`改变世界`、`赋能`。
4. **不要**把 LinkedIn 式经历时间轴塞进 profile README；本类声音用 **作品列表** 代替履历墙。
5. **不要**假装维护 50 个「essential」包；sindresorhus 的模块哲学要学的是 **小而专注的表述**，不是数量攀比。
6. **不要**中英混排口号化（「Hello 大家好我是xxx🚀」）；要么干净英文，要么干净中文，专有名词原文插入即可。

**学生页最小模板（精神对齐，非抄袭）**：

```markdown
# Your Name

CS student. Building small tools I actually use.

## Now
- Learning X by shipping Y
- Notes / blog: <link>

## Projects
- **project-a** — one-line outcome
- **project-b** — one-line outcome
- **project-c** — one-line outcome

## Contact
email@school.edu
```

## 6. Anti-patterns of this style（本风格的反模式）

即使你「想走极简工匠」，以下写法也会立刻掉出该品类：

| 反模式 | 为何冲突 |
| --- | --- |
| **假极简**：只剩名字 + 「Full-Stack Developer」无作品 | 极简的是修辞，不是信息；没有高信号就只是空白 |
| **静音到失语**：零人格、零 Now、零链接 | Paco/antfu 仍有温度与可联系方式 |
| **伪谦虚表演**：大量「菜鸡」「啥也不会」 | 工匠是克制自信，不是自我贬低梗 |
| **Opinionated 傲慢**：只骂生态、不给 fork/自定义出路 | antfu 在强硬观点旁仍写 fork / review updates |
| **徽章军备竞赛** | badge 变装饰后，信号密度下降 |
| **长篇英雄旅程** | 本类不靠故事高潮；靠持续小而清楚的产出陈述 |
| **模板腔开场** | `Hi 👋 I'm a passionate developer from …` + 动画波形 = 另一品类 |
| **堆叠头衔** | 「学生 / 创始人 / 架构师 / KOL」并列会破坏 spare 气质 |
| **过度文学化** | 「寻求存在意义」作唯一 bio 可以（sxzz），但学生页需再补一行可核验事实，否则像半成品诗 |

## 7. Synthesis for the polish project（给本项目的合成建议）

若目标 profile 选定 **Minimal craftsman**：

1. **主声参考**：Paco（结构与句长）+ antfu（温和第一人称与双语分寸）  
2. **技术文案参考**：Sindre 包 README（标题一句、用途一句、安装一块）  
3. **中文页参考**：sxzz（作品/团队链接优先，终端或列表美学可选）  
4. **验收标准**：删掉所有形容词后，页面是否仍能回答——你是谁、你在做什么、点哪里看证据？

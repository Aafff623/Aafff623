# 02 · Narrative maker / storyteller

> 研究目标：为 Software Engineering 学生的 GitHub Profile polish，提炼「叙事型 maker」声线——温暖第一人称、把 shipping 写成旅程故事。

---

## Category definition

**Narrative maker / storyteller** 指一类 indie hacker / maker 的写作声线：

- **人称**：几乎总是第一人称 `I`，读者像在跟朋友听故事，而不是读简历或技术文档。
- **结构**：时间线驱动——失败 → 转机 → 密集 shipping → 产品市场契合 → 反思教训；数字与情绪并置。
- **主题**：不是「我会什么技术」，而是「我如何一路做出东西、搞砸过什么、又为何继续」。
- **语气**：温暖、坦诚、略带幽默；愿意写焦虑、抑郁、被炒、第一美元时在卧室乱跳——再落到可执行的教训。
- **证据**：用具体里程碑（天数、MRR、用户数、Product Hunt 名次）证明故事不是鸡汤。
- **与其他声线的边界**：比「干练工程师」更情绪化；比「增长黑客文案」更个人；比「技术深度博主」更少架构细节、更多人生与产品弧线。

对 GitHub Profile 的可迁移核心：**用一条短旅程句 + 若干「已 ship 的证据」**，让访客在 10 秒内感到「这人在路上，而且在交付」。

## Catchphrases / wording habits + example quotes

### 共同词汇场

| 习惯 | 典型措辞 | 功能 |
|------|----------|------|
| 公开承诺 / 挑战框 | `12 startups in 12 months`、`ship like a madman`、`build in public` | 把模糊愿望变成可叙事的约束 |
| 速度与交付 | `ship fast`、`in 31 hours`、`in 2 weeks`、`launch viral, repeat` | 证明执行力 |
| 自由动机 | `buy freedom`、`working for myself`、`0 employee` | 解释「为何 ship」 |
| 痛与反转 | `failed spectacularly`、`roller coaster`、`it changed my life` | 制造弧线可信度 |
| 教训清单 | `Don't fall in love with your code`、`Ship early, ship small, ship frequently` | 故事收尾可复用 |
| 数字作钩子 | `$0 to $65k`、`zero to $45K/mo`、`And that's how I got my first ever internet dollar` | 标题即故事节拍 |

### Pieter Levels — 习惯与原句

- **习惯**：把心理状态与 shipping 绑在一起；用「我们（创作者）都有这个问题」拉近距离；反 guru、亲动手。
- Quotes:
  - > "My challenge is to actually finish and launch my projects. So for the next 12 months, I've set the goal to launch 12 startups in 12 months."  
    — [levels.io/12-startups-12-months](https://levels.io/12-startups-12-months)
  - > "We are scared shitless to launch 'our baby' we spent months on building out into the world."  
    — 同上
  - > "I know posts like this don't fit the whole positive 'we're crushing it' startup mantra, but at least it's real. I like radical honesty…"  
    — [levels.io/love-anxiety-and-startups](https://levels.io/love-anxiety-and-startups)
  - > "The twelve startups project made me more productive, successful and changed my life completely."  
    — 同上
  - GitHub 标签式幽默：`Chief Shitposting Officer @ Levels Synergies & Co`（[github.com/levelsio](https://github.com/levelsio)）——叙事人格延伸到 profile，但不是正式「关于我」长文。

### Marc Lou — 习惯与原句

- **习惯**：副标题先给戏剧钩子；用子弹列表堆「2 年战绩」；章节名像小说（`4 years of failure` / `I fell in love` / `Product market fit`）；收尾给「过去的我」建议。
- Quotes:
  - > "After being fired by Tai Lopez in November 2021, I launched startups like a madman to buy freedom."  
    — [newsletter.marclou.com … solopreneur story](https://newsletter.marclou.com/p/my-solopreneur-story-0-to-65k-month-in-2-years)
  - > "I wanted freedom. I was living in Bali with my Korean wife, $20,000 in the bank, no audience, and bad coding skills."  
    — 同上（具体场景 = 可信度）
  - > "Ship fast, launch viral, repeat."  
    — 同上
  - > "Don't fall in love with your code: Most startups fail. Keep shipping until one startup hits product market fit."  
    — 同上
  - > "My happiness comes from creating, not consuming."  
    — 同上
  - GitHub bio 压缩叙事：`making stuff`（[github.com/marclou](https://github.com/marclou)）——极简仍是 maker 身份句。

### Tony Dinh — 习惯与原句

- **习惯**：工程师出身写「失败的完美主义」→「零测试快速 ship」的反差；日期精确；把情绪动作写进句子（`I jumped like crazy`）；教训可清单化。
- Quotes:
  - > "Today is exactly 2 years since I quit my job and become a full-time indie hacker."  
    — [news.tonydinh.com … solopreneur story](https://news.tonydinh.com/p/my-solopreneur-story-zero-to-45kmo)
  - > "As a good software engineer, I wanted the app to have a beautiful UI, tons of features, a comprehensive architecture, and a unit test suite with >95% test coverage. … It failed spectacularly."  
    — 同上
  - > "And that's how I got my first ever internet dollar. I jumped like crazy in my bedroom in Singapore…"  
    — 同上
  - > "Ship early, ship small, ship frequently. Don't stuck on one idea for too long if it doesn't work."  
    — 同上
  - > "I was so annoyed by how ChatGPT slowly typed out the answers + kept logging me out every day, so I built a new UI on top of its API."  
    — [Making $22K in 7 days](https://news.tonydinh.com/p/making-22k-in-7-days-the-story)（从个人痛点起笔）
  - GitHub bio：`Write code, build the world 🌍`（[github.com/trungdq88](https://github.com/trungdq88)）——志向句 + 行动动词。

## Sentence patterns

可复用句式（英文骨架；中文注释用途）：

1. **时间锚点开场**  
   `Today is exactly N years since I …` / `On [date], I …`  
   → 立刻进入旅程，而非能力列表。

2. **对比钩子标题**  
   `$0 to $X/month in N years` / `$A → $B in N days`  
   → 弧线压缩成一行。

3. **问题命名 → 公开约束**  
   `We creatives have one common problem: finishing things. … So I've decided to …`  
   → Levels 式：共情 + 自我实验。

4. **场景四要素句**  
   `I was [地点] with [关系人], $X in the bank, no audience, and [弱点].`  
   → Lou 式：一句话立住起点。

5. **失败特写 + 收获**  
   `It failed spectacularly. But at least I got …`  
   → Dinh 式：允许失败，立刻回收学习点。

6. **战绩子弹列表**  
   `Over the past two years, I have:` + 动词开头条目（`launched` / `built` / `grew` / `survived`）  
   → 故事正文前的「证据预告」。

7. **情绪动作句**  
   `I jumped like crazy in my bedroom…` / `I was blown away.`  
   → 成功时刻写身体反应，比写「excited」更有画面。

8. **痛点 → 所以我做了**  
   `I was so annoyed by …, so I built …`  
   → 产品动机句，极适合 README 项目描述。

9. **规则三连**  
   `Ship early, ship small, ship frequently.` / `Ship fast, launch viral, repeat.`  
   → 可作 profile 的 Now / Philosophy 一行。

10. **给过去的自己写信**  
    `What I'd tell myself if I started again:` + 短句列表  
    → 长文收束；profile 可缩成 1–2 条信念。

11. **反神话短刺**  
    `A startup doesn't have to be a … $1B+ company from the start. That's a myth.`  
    → 降低读者心理门槛，拉近学生读者。

12. **极简身份标签**  
    `making stuff` / `Write code, build the world`  
    → GitHub bio 层：动词优先，职称其次。

## Steal-for-profile do/don't

面向：**Software Engineering 学生** 的 GitHub Profile / README（非已盈利 solopreneur）。

### Do ✅

| 做法 | 说明 | 改写示例方向 |
|------|------|----------------|
| 用一条「旅程句」当 tagline | 借 Levels/Lou/Dinh 的第一人称弧线，但换成学生真实约束 | `I learn by shipping small tools — one project at a time.` |
| 写「已交付」而非「感兴趣」 | 对应 `ship` / `launched` / `built` | `Shipped a course-planner used by N classmates` |
| 保留一个具体起点场景 | 借 Lou 的「地点/资源/弱点」压缩法，但诚实 | `Started with course projects and late-night side apps; still figuring out distribution.` |
| 失败用一句收束 | 借 Dinh：`failed` + `but I learned` | `Overbuilt my first app for months — now I ship MVPs in weeks.` |
| 项目描述用「痛点 → 所以我做了」 | 借 TypingMind 式动机句 | `I kept losing track of X, so I built Y.` |
| Bio / About 动词优先 | 借 `making stuff` 的简洁 | `Building things. Writing down what I learn.` |
| 用「Now」显示动量 | 与 narrative 配套：故事要有「当前章节」 | `Now: finishing X, writing about how I built Y` |
| 数字要可核验且学生级 | 星标、用户、作业采用量、演示链接 | 宁可用 `12 stars` / `demo live`，也不编 MRR |

### Don't ❌

| 避免 | 原因 |
|------|------|
| 照搬 `$65k/mo`、`0 employee`、`buy freedom`、Bali 人设 | 与 SE 学生身份错位，读起来像 cosplay indie hacker |
| README 写成完整 solopreneur 长篇（7 分钟阅读） | Profile 是门面；长故事放到 blog / 单篇 repo |
| 假装「build in public 大 V」却无 pinned 空壳 | Narrative 依赖证据；无 ship 则故事塌陷 |
| 堆 emoji / typing SVG /「we're crushing it」空话 | 与 Levels 强调的 radical honesty 相反；也像模板农场 |
| 用「serial founder / maker of the year」自称 | 头衔膨胀；用作品说话 |
| 把抑郁、被炒等重情绪原样搬进招聘向 README | 长文里真诚有力；学生求职 profile 宜轻量坦诚（挫折一句即可） |
| 技术栈墙代替故事 | Narrative maker 不是 badge 收藏家；3–5 个真实栈即可 |

### 学生向「偷师」迷你模板（声线，非抄袭事实）

```markdown
## Hi, I'm [Name]
I learn software by shipping small things and writing the messy parts down.

**Recent ships**
- [Project]: I needed X for [class/club], so I built Y — [link / metric]
- [Project]: …

**Now:** building … · learning …

I used to over-plan. Now I prefer: ship small → get feedback → iterate.
```

## Anti-patterns

1. **收入 cosplay**  
   标题党式 `$0 → $XXXk` 却无可点开产品——叙事 maker 的可信度来自可验证交付，学生尤忌。

2. **只有励志没有情节**  
   `Passionate developer who loves coding` 不是故事；没有时间点、失败、转折、交付物。

3. **Guru 腔 / 成功学腔**  
   Levels 明确反对的「crushing it」与卖课口吻；学生 profile 若充满 `hustle`、`10x`、`grindset`，会稀释真诚。

4. **完美主义残骸当作品集**  
   Dinh 反面教材：半年架构 + 95% 测试覆盖却未上线——profile 若全是半成品 WIP，叙事停在「Problem one: finishing」。

5. **情绪过载、无行动句**  
   只写焦虑/迷茫，没有 `so I built` / `so I launched`——变成日记，不是 maker 叙事。

6. **把别人的弧线复制粘贴**  
   「被炒 → Bali → 17 products」是 Lou 的生平，不是声线许可证；偷的是句式与诚实密度，不是传记。

7. **GitHub 与博客声线断裂**  
   Blog 很会讲故事，GitHub bio 却是空洞 `Student | Actively looking`——应用同一套动词与「当前章节」。

8. **指标陈旧或不更新**  
   「Indie Builder」模式依赖动量；过期的「Now」和假 MRR 会反噬信任（参见 [devbio Indie Builder 模式说明](https://devbio.me/blogs/github-profile-readme-templates)）。

9. **叙事淹没可扫描信息**  
   招聘官/协作者仍需 30 秒内找到：你会什么、做什么、怎么联系。故事是调味，不是唯一图层。

10. **幽默越界成低质 shitpost**  
    Levels 的玩笑建立在大量真产品之上；学生若只有玩笑没有 repo，会像不认真。

## 研究备注（简）

- 三位样本均以 **第一人称旅程文** 为品牌核心；GitHub 侧反而常极简（`making stuff` / 短句 bio），长叙事放在 levels.io / Substack。
- 对学生 polish：**声线偷「弧线 + 动词 + 痛点起因」**，**事实留在自己的课设/side project**；一篇 pinned README 或 About 用 5–8 行讲完「我是谁 → 我 ship 了什么 → 我现在做什么」即可。
